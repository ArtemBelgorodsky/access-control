# Проверка приложения

Автоматические проверки: `npm test` — 17 тестов бизнес-логики, адаптера REST API и формирования CSV.

Проверяются: отказ неизвестному лицу, сохранение местоположения после отказа, переход между помещениями, повторный вход, некорректный выход, блокировка входа и разрешённый выход заблокированного сотрудника, расписания и периоды дат, ночные смены, вместимость, порог сходства, неоднозначные совпадения, несколько эталонов одного сотрудника, длительность посещений, московская дата, валидация URL, ошибки записи, формат ответа и передача токена.

Сборка: `npm run build`.

## Проверка в браузере

При первичной проверке, до удаления демонстрационного входа, локально проверены:

- Вход администратора и загрузка локальных данных.
- Создание карточки сотрудника.
- Успешный переход между помещениями и отклонение повторного входа.
- Регистрация лица по фотографии и сохранение изображения/признаков в IndexedDB.
- Проверка по **другому** снимку того же человека: лицо сопоставлено с зарегистрированной тестовой карточкой, проход сохранён.
- Проверка фотографии другого человека: сопоставление отклонено, записан отказ.
- Выход по фотографии и отсутствие сотрудника в списке присутствующих после выхода.
- Отчёт по посещениям и ограничение интерфейса руководителя сотрудниками своего подразделения.
- Адаптивная компоновка на ширине 1440 и 390 пикселей.

CSV проверен на кодировку UTF-8, разделители, кавычки и нейтрализацию формул. Нажатие экспорта в браузере не вызывает ошибок; получение файла через событие загрузки встроенного браузера не подтверждено (ожидание события истекло). Сохранение файла следует проверить в обычном Chrome/Edge.

Использованы общедоступные примеры `obama.jpg`, `obama2.jpg`, `biden.jpg` из репозитория https://github.com/ageitgey/face_recognition/tree/master/examples . Они применяются исключительно как тестовые пары изображений в локальном режиме; в Mokky не загружались.

На этой тестовой паре оценка сходства разных снимков одного лица составила около 0.53, другого лица — около 0.43. Начальный порог 0.50 соответствует учебному примеру; эти значения **не являются оценкой точности** на других людях. Для дипломной экспериментальной части нужны дополнительные сотрудники, независимые снимки разных ракурсов и подсчёт ложных допусков/отказов.

Чтение всех восьми ресурсов пользовательского проекта Mokky проверено. Данные проекта при проверке не изменялись. Регистрация пользователя, запись событий и загрузка файлов в удалённый Mokky требуют включённых функций авторизации/загрузки и входа пользователя; удалённая запись без его учётной записи не проверялась.

Для повторения фото-проверки разработчиком: `node scripts/download-test-fixtures.mjs` скачивает три тестовых файла в игнорируемую папку `test-results/fixtures/`. Эта команда не запускается при обычном старте приложения.

После обновления экрана входа проверено: форма содержит только email и пароль; выбор деморежима, адрес проекта и название провайдера убраны. Прежние демонстрационные сессии без токена не восстанавливаются. Приложение использует подключённый REST API. Сборка и все 17 автоматических тестов проходят.

## Подготовка к Vercel

- Добавлены `vercel.json`, Node.js 24.x и `.env.example`; CMD-запуск и отдельный скрипт раздачи файлов удалены.
- `npm run build` копирует модели, собирает приложение и проверяет наличие ресурсов в `dist`.
- Проверены production HTML, JSON модели и бинарные веса по HTTP: ответ 200 с соответствующими типами содержимого.
- В отдельной тестовой сборке подтверждена подстановка `VITE_API_BASE_URL`; основной `dist` сохраняет пользовательский адрес API.
- CORS проверен с тестовым Origin на домене `vercel.app`: чтение разрешено, OPTIONS авторизации вернул 204 и разрешил `authorization,content-type`.
- `npm test`: 17 из 17. Фактическая публикация в аккаунте Vercel не выполнялась.

Последнее упрощение настроек: на странице оставлены только порог сходства и сохранение. Блоки подключения, адреса, сведений о системе, предупреждения и резервной копии удалены из интерфейса. Адрес API закреплён в `src/services/api.js`, переменная окружения адреса больше не используется. Проверено серверным рендерингом компонента: старый адрес из localStorage игнорируется, порог восстанавливается и сохраняется отдельно. Сборка и 17 тестов проходят.

## Светлый дизайн интерфейса

Переработаны общие стили, навигация, вход, сводка, карточки занятости и точка контроля. Manrope с кириллицей поставляется локально вместе со сборкой. В мобильной навигации добавлены `inert` для закрытого меню, `aria-expanded` и закрытие по Escape.

В браузере визуально проверены вход и переключение формы первого запуска без отправки данных. Для авторизованных страниц использован серверный рендеринг существующих Vue-компонентов с локальными тестовыми данными в игнорируемой папке `test-results/design-preview`; это статические макеты для проверки вёрстки, а не дополнительный режим приложения. Удалённые данные и пользователи не изменялись.

Проверены сводка, занятость, сотрудники, помещения, разрешения, точка контроля, журнал, отчёты и настройки на ширине 320 пикселей: переполнения страницы нет, широкие таблицы прокручиваются в своих контейнерах. Отдельно проверены вход и сводка на 390 пикселях, сводка, занятость и точка контроля на 1440 пикселях. Исправлены переполнение кнопок заголовков и показателей отчёта на узком экране. Скриншоты находятся в `output/redesign-*.jpg`.

Production-сборка с локальными шрифтами и моделями распознавания проходит; 17 автоматических тестов проходят. Публикация в Vercel не выполнялась.
