# Рубеж — управление доступом сотрудников

Учебное веб-приложение на Vue 3. Собственный backend и PostgreSQL не нужны. Распознавание фотографий выполняется в браузере с Human; данные хранятся в подключённом проекте Mokky.dev. Вход выполняется по email и паролю.

## Деплой на Vercel

1. Загрузите исходники проекта в репозиторий GitHub. Не загружайте `node_modules`, `dist`, `.env.local`, `output` и `test-results` — они указаны в `.gitignore`.
2. В Vercel выберите **Add New → Project** и импортируйте репозиторий.
3. Если проект лежит в корне репозитория, оставьте **Root Directory** по умолчанию. Иначе укажите папку с `package.json` и `vercel.json`.
4. Проверьте параметры сборки:

| Параметр | Значение |
| --- | --- |
| Framework Preset | Vite |
| Node.js | 24.x |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

5. Переменные окружения для адреса API не требуются: адрес проекта закреплён в `src/services/api.js`.
6. Нажмите **Deploy**. После успешной сборки откройте выданный HTTPS-адрес и войдите в приложение.

Настройки записаны в `vercel.json`. На Vercel публикуется статическая папка `dist`; отдельный постоянно работающий сервер не требуется. Команда `npm start` для деплоя не используется.

Модели распознавания входят в npm-пакет Human. При установке и перед сборкой они автоматически копируются в `public/models`, затем включаются в `dist/models`. Добавлять их вручную в GitHub не нужно. Распознавание остаётся в браузере пользователя; записи и фотографии сохраняются через подключённый API.

Навигация использует адреса вида `/#employees`, поэтому дополнительные SPA-перенаправления не нужны. Запросы `/models/*.json` и `/models/*.bin` должны возвращать файлы моделей, а не HTML страницы входа.

Адрес API задан в исходном коде и не редактируется в интерфейсе. Сохранённые ранее настройки другого адреса не используются. Вызовы API выполняются из браузера; сервис должен разрешать CORS с адреса приложения. Если провайдер поддерживает настройку разрешённых доменов, добавьте домен Vercel и используемые Preview-домены.

Подготовка к деплою не публикует приложение автоматически. Фактический деплой и вход в учётную запись выполняются в вашем Vercel.

Документация: [Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite).

## Локальная разработка

Установите Node.js **24.x**, затем выполните в папке проекта:

```sh
npm ci
npm run dev
```

Для проверки production-сборки: `npm run build`, затем `npm run preview`. Папка `dist` содержит ту же статическую версию, которая публикуется на Vercel.

## Вход и подключение Mokky

Адрес проекта уже указан: `https://c748fc988f763776.mokky.dev`.

В панели Mokky создайте ресурсы-массивы: `employees`, `departments`, `positions`, `rooms`, `access_levels`, `permissions`, `face_templates`, `access_events`. Их начальная структура приведена в `mokky/`. При уже заполненных ресурсах не заменяйте содержимое без резервной копии.

Включите авторизацию, регистрацию и загрузку файлов. Ресурсы `users` и `uploads` создаются штатными настройками Mokky. Защитите ресурсы авторизацией и разрешите необходимые методы: GET/POST/PATCH, для `permissions` и `face_templates` также DELETE. Публичное чтение `users` включать не нужно.

На экране входа выберите «Первый запуск? Создать администратора». Укажите своё имя, email и новый пароль (от 8 символов). Приложение регистрирует учебную учётную запись через `/register` с `role: "admin"`. Пароль не сохраняется в браузере; токен текущей сессии хранится в sessionStorage. Учётные записи охраны и руководителя добавляются в разделе «Пользователи».

Переключатель деморежима удалён. Адрес проекта настроен заранее и не отображается на экране входа. Старые сессии демонстрационного входа больше не принимаются.

## Проверка дипломного сценария

1. Откройте «Сотрудники», добавьте своего сотрудника или измените тестового.
2. Назначьте ему уровень доступа; в «Права доступа» проверьте помещения и расписание. Время — московское. Для проверки ночью или в выходной задайте соответствующий интервал/дни.
3. В строке сотрудника нажмите значок распознавания. Загрузите 3–5 фотографий с небольшими поворотами головы. Требуется одно лицо на снимке.
4. Откройте «Точка контроля», выберите помещение и «Вход».
5. Загрузите **другое фото** того же сотрудника и нажмите «Проверить проход».
6. Проверьте результат в журнале и появление сотрудника в «Занятости помещений».
7. Зарегистрируйте выход. Проверьте, что сотрудник больше не находится в помещении.
8. Проверьте отказ при отсутствии разрешения, блокировке сотрудника или нарушении расписания. Отказы не меняют местоположение.

Отдельный режим **«Ручная имитация»** проверяет правила доступа без распознавания. В журнале он явно помечен.

## Возможности

- Сотрудники, подразделения, должности, помещения, оборудование и уровни доступа.
- Индивидуальные и групповые разрешения с днями недели, интервалом времени и периодом дат, включая ночные интервалы.
- Загрузка фотографий и вычисление признаков лиц; отказ при отсутствии лица, нескольких лицах и неоднозначном совпадении.
- Контроль вместимости, переходы между помещениями и защита от повторного входа.
- Учёт занятости по успешно зарегистрированным проходам. При неизвестном местоположении система не предполагает присутствие.
- Журнал и отметка нарушений как просмотренных; фильтры и экспорт CSV.
- Отчёты по сотрудникам, подразделениям и помещениям, включая длительность посещений и незакрытые визиты.
- Роли администратора, службы безопасности и руководителя подразделения; управление учебными учётными записями.
- Настройка порога сходства лиц.

## Ограничения учебного прототипа

Это демонстрационная система, не готовая защита физических дверей. Роли и решения проверяются в браузере, поэтому их можно обойти прямыми запросами. Mokky и клиент не обеспечивают серверные транзакции, неизменность журнала и защиту от одновременных проходов с разных компьютеров. Для промышленной СКУД необходим сервер с принудительными проверками и атомарной записью событий.

Успешная проверка **имитирует** состоявшийся проход. Без датчика нельзя узнать о незарегистрированном выходе. Заблокированный сотрудник может зарегистрировать выход из текущего помещения.

Распознавание не гарантирует совпадение при сильном профиле, размытии, закрытом лице и плохом освещении. Начальный порог — 0.50, минимальный отрыв от другого сотрудника — 0.06. Эти параметры требуют проверки на независимых фотографиях ваших сотрудников; два тестовых лица не определяют точность всей системы. Оценка сходства не является вероятностью. Нет проверки живого человека: входными данными по заданию служат фотографии.

Для Mokky нужны интернет и доступные ресурсы. При ошибке записи успех не показывается. Если ответ на запись потерян, проверьте сохранение, прежде чем начинать новую попытку. Идентификатор операции уменьшает риск повторов, но не заменяет серверную уникальность.
